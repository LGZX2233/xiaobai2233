# Repository layout

This independent kernel repository separates runtime implementations, tests, development workflows and historical acceptance evidence. The [module tree](../modules/README.md) owns functional navigation; [test ownership](../../tests/README.md) owns test locations.

Document version: 1.0.0. Updated: 2026-10-10 (Asia/Shanghai, date precision). Source baseline: project 1.0.0 at `0a619766162682606ad57a9aa4c1926d54c1b891`; current test relocation and documentation remain uncommitted. Requirement: [REQ-SG-01/07](../requirements/2026-10-10-clean-layout-and-skill-growth.md). Runtime acceptance: unchanged historical G2; this layout has only static verification recorded in the current task.

| Directory | Responsibility |
| --- | --- |
| `src/project_kernel/` | Python domain, application, data, provider and interface implementations |
| `bridge/protocol/` | Node runtime protocol client and canonicalizer |
| `tests/` | Python suites, Node bridge suites, test-only hosts and shared test vectors |
| `contracts/v1/` | Frozen protocol inputs and digest examples |
| `fixtures/` | Committed deterministic input fixtures |
| `tools/` | Explicit development and evidence-management commands |
| `.agents/skills/` | Project workflow instructions |
| `docs/modules/`, `docs/requirements/`, `docs/records/` | Module navigation, requirement ownership and maintained task/project records |
| `docs/acceptance/` | Existing acceptance decisions, signatures, manifests and raw evidence |

Generated bytecode and cache directories do not belong in runtime source directories. `.gitignore` excludes Python cache and local test output paths. `.validation-tmp/` is isolated scratch storage that also contains earlier failure captures; those captures are retained and are not current acceptance evidence.

Ignoring bytecode does not prevent Python from creating it. When running Python locally, use its `-B` option or a `PYTHONPYCACHEPREFIX` outside the functional directories when bytecode caching is wanted. This is local development guidance, not a new kernel setting or runtime guarantee.

## Bridge test migration

| Original path | Current path |
| --- | --- |
| `bridge/protocol/client_test.mjs` | `tests/bridge/client_test.mjs` |
| `bridge/protocol/golden_test.mjs` | `tests/bridge/golden_test.mjs` |
| `bridge/protocol/kernel_stdio_test.mjs` | `tests/bridge/kernel_stdio_test.mjs` |
| `bridge/protocol/vectors.json` | `tests/bridge/vectors.json` |

The Node tests import runtime modules using `../../bridge/protocol/`. Their repository root remains two directories above the test files, so frozen contract paths and the Python stdio host remain at their existing locations. `tests/p10_protocol/test_vectors.py` reads the relocated shared vectors. The vector file retains its original bytes; the Node test imports and path comments change with their locations.

Existing signatures, captures, manifests, third-round materials and ZIPs retain their original paths and recorded hashes. The table maps historical paths to the current tree without rewriting those records. The [current task record](../records/tasks/2026-10-10-layout-and-skill-growth.md) records this migration and its actual static checks. Syntax, path and hash inspection do not establish runtime behavior or renew acceptance; no tests or behavior probes are run for this migration.
