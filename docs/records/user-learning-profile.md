# 用户学习画像

本页用可纠正的文字记录已确认偏好和学习需要，帮助调整技术路线说明与对话深度。它不评分、不排名，不作为权限依据，也不从一次提问、报错或代理操作推断用户的能力。规则见[持续记录架构](../architecture/continuous-records.md#修订撤回与删除)。

## 已确认的偏好和需求

以下内容来自用户于2026-10-10的明确要求；知识熟悉程度仍以用户确认的描述为准，当前没有对话节点关联。

| ID | 已确认内容 | 适用方式 | 有效范围 |
| --- | --- | --- | --- |
| UP-001 | 信息和用户画像不采用评分；需要可修改、模型可阅读的文档 | 用文字说明事实和未知，不生成能力分数或综合得分 | 持续记录设计 |
| UP-002 | 每次任务有总结，项目有总体总结，词语和错误有分析 | 完成或交接工作时维护对应记录，引用需求、模块和来源 | 持续记录设计 |
| UP-003 | 知识熟悉程度会随学习变化，记录需持续更新 | 接受用户修订，不把早期状态永久化 | 学习画像 |
| UP-004 | 希望依据知识熟悉程度推荐技术路线并改进对话；不理解的内容整理学习资料 | 知识程度未知时先给必要概念和项目实例，不默认其已掌握或不掌握 | 技术路线与解释 |
| UP-005 | 模块树本轮只文档化；节点详尽，含需求、验收、版本、更新时间，关系明确；允许空和多对多 | 从节点进入主文档，避免强制一对一和重复事实 | 本轮模块文档 |
| UP-006 | 保持内核干净、结构清晰 | 文档记录与运行内核分清职责，新增能力不凭文档默认接线 | 内核维护 |
| UP-007 | 本轮不用测试 | 不启动测试或行为探针；结果如实说明验证限制 | 当前任务，不推导为永久禁止测试 |
| UP-008 | 文档面向用户阅读，技能应随经验成长改进；技能可以评分，用户画像不评分 | 入口先说明用途与限制，逐步提供详情；按方法的实际效果改进技能，不把技能评价转成用户能力评价 | 当前文档与技能维护 |

## 知识熟悉程度

| 知识主题 | 当前描述 | 来源与更新条件 |
| --- | --- | --- |
| Python、Node 与 RPC | 未知，未建立熟悉程度结论 | 等待用户明确描述或确认；代理完成相关工作不代表用户掌握 |
| 数据库、版本账本与效果对账 | 未知，未建立熟悉程度结论 | 等待用户明确描述或确认 |
| 模块树、关系图、多对多 | 用户提出了相应需求；知识熟悉程度未知 | 需求本身不证明或否定概念熟悉程度 |
| 可插拔规则与 skill | 用户提出了扩展建议；知识熟悉程度未知 | 后续以用户确认的学习需要更新 |

可在用户确认后使用“能独立使用”“了解概念”“需要例子”“正在学习”等描述。这些是可选表达，不是有高低排序的等级；同时记录适用主题和具体说明，不将一个主题的描述推广到全部技术。

## 推断与未确认信息

当前没有采纳的模型推断。未经用户确认的假设需标出依据和适用范围，不作为既定偏好或知识水平。推荐技术路线仍须结合任务目标、环境和源码限制，画像不替代这些事实。

## 学习资料入口
