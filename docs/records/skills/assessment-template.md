# Skill 复用评估模板

此页是填写说明，不是一项已执行评估。仅在实际复用后建立记录；反馈复核可采用[现有反馈记录](2026-10-10-maintain-records-review.md)的必要字段。删除不适用的段落，内容围绕本次判断组织。

## 定位

记录 `record_id`、`record_version`、`updated_at`、`timezone`、`source_revision`、`source_worktree`、`skill_id`、`skill_version`、`status` 和 `validation_status`。版本来源、记录状态和索引定义见[成长方法](../../architecture/skill-growth.md#最小索引与状态)。没有 skill 提交时写工作树范围，勿用源码 SHA 代替。

## 请求、适用与证据

写出本次请求与读者或调用者目标、已满足的前提、所用方法与版本，以及来源链接和实际结果。区分运行观察、静态核对、用户反馈和推断；注明未观察内容。说明为何适用，有无人工纠正、额外工具或环境因素影响结果。没有实际复用时，不登记为成功观察。

## 分维度评价

| 维度 | 0/1/2/null | 证据、理由与限制 |
| --- | --- | --- |
| `correctness` | null | 按实际要求判断，未知保持 null |
| `applicability` | null | 前提和范围的实际匹配情况 |
| `reuse_benefit` | null | 与明确对照的收益；无对照不补分 |
| `maintainability` | null | 维护及读取成本；2 表示容易维护和读取 |

各维度解释见[评价定义](../../architecture/skill-growth.md#评价什么)。不评分用户，不计算平均总分；分值只描述本次观察。

明确评分单位是本 skill 版本在本次请求、前提和证据范围内的表现。不同版本/场景不默认汇总，外部工具失败不自动导致 correctness=0；没有观察或对照时保留 null。评分输出只有数据处理用途，不改变执行、验收或授权，详见[接口范围](../../architecture/skill-growth.md#数据处理接口与评分范围)。

## 失败分析与总结

实际失败时填写：预期与实际、输入/skill/工具版本、前提匹配、失败阶段与时间线、原错误及回执证据、候选原因的支持/反证/排除、已确认根因与未决项、影响及外部效果状态、纠正/撤回、修订及复验结果。按[失败分析要求](../../architecture/skill-growth.md#调用失败的分析与总结)链接任务主记录，不重复大日志。没有失败时写不适用；静态发现或假设不是调用失败。

简述失败阶段与症状、确定/未知原因、影响、修正及复验状态。根因未知时写明缺失证据和下一项可区分原因的观察；未复验时保持未复验。确认重试已有授权和状态允许，不由评估记录触发执行重放。

## 复核决定与跟进

写明适用的触发建议或调整原因、是否进入 `review_required` / `suspended`，并分类为方法问题、范围问题、过期或调用误用，可组合或未确定。指出问题范围、复核问题、所需修订和下次观察目标。无需复核时也写明本次证据支持到什么范围，不因此宣布整个 skill 已验证。

修订另记旧版本、新版本、依据、修改和未解决问题，更新 registry 引用。新版本先为 `trial` / `not_validated`；关联后续实际观察及明确复核决定。保留纠正、撤回或替代依据，遵守当前验证授权。
