# 独立内核项目后续计划

更新日期：2026-10-10（Asia/Shanghai）。本页只列项目顺序；当前能力和接受范围见[内核现状](../architecture/current-state.md)，内核维护细项见[实施计划](2026-10-09-kernel-remediation-next.md)。

## 已确定的项目边界

- `kernel_next`：项目事实、执行流、审批、证据、恢复、RPC 和 provider ports。
- DSH adapter：会话、模型、工具、沙盒、取消、身份和平台事件映射。
- Workbench frontend：项目化工作区、流程图、表单、实时状态和可视化留档。
- Git provider：后续能力；代码仓库已经初始化并同步，仓库 push 不等于内核提供 Git 交付效果。

## 顺序

1. 处理[静态设计审查](../reviews/2026-10-10-design-review.md)中的核心 RPC 异常处理缺口，保留独立核心接受的范围与历史证据。
2. 内核维护稳定后，在新授权范围内建立 DSH adapter 的项目绑定、断线恢复、取消、沙盒、来源 flush 和人审回调；逐能力接受 G3。
3. 另建前端项目，把设计、执行、验收、申请、审批、交付、归档呈现为项目工作区，按真实宿主与浏览器行为接受 G4。
4. [模块导航及学习记录](../requirements/2026-10-10-continuous-records.md)已按文档与 skill 交付；自动运行集成另行定义。需要可选知识/语料时，先处理知识提升授权与效果持久化，再独立开展 G2-K。
5. Git provider、分发安装包、真实试点和生产恢复分别定义目标、权限及验收，不从仓库同步或 G2 测试推导已经可用。

交付 provider 拆分、独立仓库同步和第四轮 G2 接受已完成，不再列为待办。第三轮和第四轮原始证据均保持历史字节；后续工作使用新文档和新证据目录，不覆盖旧轮次。

## 放行条件

G2 独立核心已 accepted_g2，不是仍待接受的候选；release_approved=false。生产放行仍需要实际部署的效果观察、明确的 unknown 恢复、真实宿主身份与沙盒、相关 adapter/workbench 端到端证据，以及维护与回滚方案。本次静态审查和文档更新不代替这些后续接受。
