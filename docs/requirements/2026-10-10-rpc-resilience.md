| ID | 要求 | 修复判据 | 实施与验证状态 |
| --- | --- | --- | --- |
| REQ-RPC-01 | 过深 JSON 不能以递归异常结束请求处理 | `json.loads` 的 `RecursionError` 转成 `FrameError`，使用原解析错误响应；后续完整帧仍经过同一处理循环 | 已实施；静态复核，无行为验证 |
| REQ-RPC-02 | 无效 Unicode 和非法 id 不能破坏错误响应 | 解码后逐项检查字符串，包括对象键；未配对代理码拒绝为解析失败；所有响应仅回显符合冻结 id 正则的 id，不先改写请求再放行校验 | 已实施；保留合法 Unicode 与冻结正则语义；无行为验证 |
| REQ-RPC-03 | 响应编码失败能产生安全兜底 | 预期序列化及 UTF-8 异常转成 `FrameError`；原大帧响应保留，其他编码失败用合法 id 返回 `-32603`；兜底再次失败返回固定 ASCII 错误，不抄原 payload | 已实施；静态复核，无行为验证 |
| REQ-RPC-04 | 文档和记录与实现一致，保留冻结资料 | 更新 RPC 节点、现状、计划、审查及错误资料，区分原发现、当前修复与未验证；冻结 Schema、旧签字及原始证据不改 | 当前维护记录另存；核对结果见任务 |
| REQ-RPC-05 | 普通提交后推送主分支 | 收入此前获授权的目录和文档工作；先读取远端 main，保留其新提交，普通合并后快进推送并核对远端 ref，工作区无遗留修改 | 首次推送及核对已完成；[同步记录](../handoffs/2026-10-10-rpc-fix-main-sync.md)保存实际提交 |
