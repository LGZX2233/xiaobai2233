# CR-009 内核模块边界与留档整改

日期：2026-10-09。范围：仅未发布的 kernel_next 内部实现。P13 负责组合，身份、来源、提供者和查询分别实施；独立审查结果写入第二轮证据，不沿用上一轮的源码指纹。

## 变更与消费者

身份入口独立使用 shared.sqlite，新增身份命令回执迁移，不修改已存在的迁移文本、冻结项目 DDL、JSON Schema 或 DTO。身份命令按可信调用者、项目和幂等键持久化回执，跨库创建保留可恢复意图；项目入口不兼任身份入口。project.bind 在显式配置身份注册表的项目入口提供，公开回执属于 project 域；身份库仅保存内部效果结果，项目意图和结算分别追加记录。最大长度公开幂等键使用有界内部结算标识。

EvidenceService 消费内部 EvidenceEffects，EnvironmentService 消费 EnvironmentProbe。FileEvidenceProvider 与 PythonEnvironmentProbe 承担外部操作；组合根负责显式装配。EvidenceService 内部构造参数改为 provider=，所有已知测试与消费者同步调整。没有发布 DSH 包或改变 Session API，不需要 DSH 用户升级步骤。

来源标识从冒号拼接改为无歧义 JSON 三元组，内部聚合按三列匹配；旧歧义游标显示 unavailable，不推测原身份。来源缺口按已接收序号生成有界样本和区间；总数、区间边界与下一缺口用十进制字符串。来源及结算验证 principal 与 provider 的明确授权，数据模式与固定执行关联不可由提供者结果覆写。

阻塞记录通过现有 revision/head_history 留存打开和解决状态，blocker 表仅为当前索引。交付开始时写阻塞，结算或对账确认终态后以精确操作 revision 解决。总览按历史水位重建，旧数据无历史时返回缺失标记；归档也按提交顺序读取，不混入未来回执。

交付对账检查操作身份、已验证的目标摘要和本项目精确 fence 证据；直接提供回执只在明确 test scope 可用，实际部署通过配置的效果查询提供者取证。恢复、环境和证据提供者返回的原始数据保留，但不能覆写固定业务关联。归档成功要求精确清单摘要和布尔 verified；record_sink_result 新增 verified 参数，成功回调调用者同步更新。缺乏验证的旧成功回执在查询中显示 unknown；精确归档版本不存在时返回 REFERENCE_NOT_FOUND。Store 每次连接核对 schema stamp，初始化异常关闭连接并释放访问锁。

## 验证与状态

本条登记允许内部增量迁移与构造注入改动，属于用户已授权的内核整改，不代表 G2 放行。验证包括正常入口、无权限与错项目拒绝、重启重放、并发同键、巨量来源缺口、提供者字段覆写反例、阻塞与归档历史，以及既有恢复与完整执行流程。最终结果以 [第二轮报告](../acceptance/G2-round2-report.md) 为准。

默认关闭知识共享和语料出口；本轮不执行 DSH、Git、真实旧工程导入、生产恢复、训练或上传。历史验收包和独立复核保留。
