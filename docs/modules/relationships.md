# 节点与关系定义

文档版本：1.0.0。更新时间：2026-10-10（Asia/Shanghai，日期精度）。[模块树](README.md)是阅读入口；[registry.json](registry.json)是导航与关系的机器可读投影；节点正文保存职责、需求和验收详情。修改正文中的关系时，在同一工作更新索引。

## 节点身份与版本

`node_id` 是稳定标识，移动源码或文档时保留 ID。导航分组也是节点，但不是额外运行服务。`document_version` 记录节点文档修订，`source_version` 记录项目声明版本，`source_revision` 是所检查源码提交；三者不能互相代替。未提交代码变化需要另加 `source_worktree_changes` 和差异说明，不能只沿用基线提交暗示已经覆盖。

每个节点正文需包含以下字段与段落：名称与 `node_id`、`node_kind`、文档版本、源码版本/提交、更新时间与精度、实现状态、导航父节点、`conversation_refs`、职责、源码入口、输入输出或持久对象、`depends_on`、`related_to`、需求记录、验收记录、限制和变更记录。字段未知时写 `unknown`，没有关系时写空列表，不能用未知代替没有。

## 关系方向

| 关系 | 方向与含义 | 基数与限制 |
| --- | --- | --- |
| navigation_parent | 子节点指向主要阅读分组 | 根为空，其余一个父节点；无环；仅用于导航，不表示调用或权限 |
| contains | 聚合节点指向其直接导航子节点 | 从 navigation_parent 反向派生，不单独存第二套索引；不表示调用依赖 |
| depends_on | 使用方指向依赖方 | 可空、可多对多；节点明确说明是运行依赖还是文档工作流依赖 |
| related_to | 发起节点指向关联节点 | 可空、可多对多；对称关联由双方各列一条，不能自动推断反向依赖 |
| requirement_refs | 节点指向需求记录中的具体 ID/条件 | 可空、可多对多；区分历史冻结需求与本轮新增要求 |
| acceptance_refs | 节点指向特定范围的接受或待验收记录 | 可空、可多对多；指向报告不表示整个节点获接受 |
| conversation_refs | 节点指向宿主对话或片段 | 本轮全部为空；以后可空、可多对多，不假造 conversation ID |
| source_entries | 节点正文指向文件和可检索符号 | 可空、可多对多；一文件服务多个节点是允许的，不为图整齐拆源码 |

`depends_on` 允许表达工作流与运行层的真实关系，不要求它们组成单一树。只有 `navigation_parent` 是树；依赖和关联另外展示。机器索引不声明不存在的运行集成：例如 K-RECORDS 对 K-RULES 的引用是记录工作流关联，不是 `bootstrap.py` 加载 skill。

## 状态与接受范围

当前实现状态采用明确文字或短标记：聚合节点、已实现核心、test-only、默认关闭可选能力、未接线 library、文档工作流。实现状态不等于验收状态。历史 G2 的具体 AC 可以与当前节点相关，但仅原25项87条件获得独立接受；新增文档关联、静态发现和用户画像没有因此自动通过运行验收。

证据文件和冻结 Schema 是事实来源，不在节点页复制原始裁决。待验收项目写清判据与 `not_run` / `not_reviewed`，不填 fabricated passed。本轮 `source_revision` 均以当前源码提交为基线，新增文档是工作区维护版本。

## 维护和删除

源码移动、责任变化、需求改变或接受状态有新裁决时更新受影响节点、关系投影和任务记录。仅改文字不需要提高源码版本。节点合并或退休时保留旧 ID 指向替代节点的记录，避免旧需求引用失效；删除画像信息按[持续记录架构](../architecture/continuous-records.md)处理，节点索引不保存个人内容。
