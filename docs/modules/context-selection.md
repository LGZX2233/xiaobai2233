# 按节点选取工作上下文

文档版本：1.1.0。更新时间：2026-10-10（Asia/Shanghai）。这是项目内 skill 的资料选取流程；没有新增 RPC、对话抓取器或自动上下文服务。

## 选取顺序

1. 在[总树](README.md)选择目标节点，读取其职责、源码入口、当前版本、需求和限制。
2. 读取本次改动实际涉及的文件和精确符号；共享文件可同时属于多个节点，不需要完整加载所有节点。
3. 读取相关需求原文与对应 AC 条件。冻结验收读取原链接，模块与记录建立要求读取 [REQ-CCR](../requirements/2026-10-10-continuous-records.md)，布局与技能成长读取 [REQ-SG](../requirements/2026-10-10-clean-layout-and-skill-growth.md)；不能把摘要代替原条件。
4. 读取目标节点的直接 `depends_on`，只选择与改动相关的部分；继续跨越下一层时说明原因。`related_to` 仅在涉及其交互时读取。
5. 读取当前问题和最近任务记录。只有推荐技术路线或解释术语时才读取适用的用户偏好/学习信息，不把未知熟悉度补成推断。
6. 记录本次选择的节点、文件/符号、版本、必要材料、可选材料和未选原因。必要资料缺失时明确未知，不能用旧摘要补造。

## 上下文清单

下表是单次任务记录可使用的字段，按实际需要填写；不是新 Kernel DTO。

| 字段 | 含义 |
| --- | --- |
| target_node_ids | 本次直接修改的节点；可以多个 |
| purpose | 修改、审查、解释或技术路线比较的具体目标 |
| source_revision / worktree_changes | 源码基线与本地差异 |
| selected_refs | 资料路径、符号或需求/AC ID、文档版本、读取日期与必要性 |
| dependency_depth | 实际选取的依赖深度；超过直接依赖说明缘由 |
| excluded_refs | 不相关、超预算、历史过期、未授权范围等排除原因 |
| gaps | 缺失事实与影响；必要资料缺失不记为已了解 |
| profile_refs | 本次确实相关且允许使用的描述性偏好；没有则空 |

上下文限制根据当前任务指定，不能为了拉齐资料把全部历史证据或完整学习画像塞入模型请求。模型需要精确事实时进入原文件；短摘要用于导航。现有[ContextResolver](nodes/knowledge.md)提供 budget/mandatory API，但本轮文档没有接入它或构造 `ContextManifest`，清单也不构成模型请求已审计的运行证明。

## 改动衔接

涉及多个模块时在同一任务记录列出所有目标节点和关系，不复制多份相同结论。完工或暂停时更新受影响节点、需求状态和[项目摘要](../records/project-summary.md)，把尚未执行的测试、接受或宿主集成保留为未完成。可复用错误解释写入[术语与错误](../records/terms-and-errors.md)，学习状态只在存在明确依据时调整。
