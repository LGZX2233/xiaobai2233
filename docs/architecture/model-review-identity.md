## 已选路线 A：模型评分审阅，人类确认入库

2026-10-12 当前会话用户明确选择“走a”。收尾模型负责比较方案、审阅验收证据、提出模块整理与去耦建议、准备入库材料；人类确认具体方案包及其依据是否可并入主库。模型或编排层可以执行已获授权且符合命令条件的动作，不能替人类授予审批。

这项选择确定职责，未授予任何具体包的入库许可，也未授权预先放行、批量放行或模型自动审批。最终入库操作还需实现模块包、收敛记录及宿主接入；现有 `approval` 不等于新模块入库流程已经存在。

## 评分、意见与审批分别是什么

现内核的 `approval.decide`、`approval.revoke`、`decision.record`、`verification.record_review`、`dataset.review` 属于 `HUMAN_ONLY_COMMANDS`（见 [RPC 访问策略](../../src/project_kernel/interfaces/rpc/policy.py)）。`approval_transition`、`revoke_approval` 在 `is_human=False` 时拒绝（见[状态规则](../../src/project_kernel/domain/flow.py)）。机器意见不能借 `verification.record_review` 写成人类复核。

| 产物或动作 | 责任与用途 | 当前状态 |
| --- | --- | --- |
| 方案评分、模型审阅意见 | 数据处理产物；绑定包版本、评分规则、测试证据与理由，供人审和方案比较 | 新的方案评分记录及接口未实现 |
| 客观验收结果 | 依固定候选和验收项形成 verification；分数高不替代必需验收项通过 | 已有验收机制，模块包绑定尚待设计 |
| 人类复核与批准 | 可信人类入口记录具体依据下的确认、拒绝或撤回 | 已有身份纪律；新主库入库确认仍待实现 |
| 执行并入及确认外部效果 | 模型或编排层在已批准范围内调用实现者；效果需由真实回执结算 | 新主库目标和 provider 尚未接入 |

知识 [ScoreEngine](../../src/project_kernel/knowledge/scoring.py) 对 use/outcome 事件加权、去重及衰减，不是方案质量评分器，也不是 skill 四维评价。方案评分需另行定义对象、规则版本及证据，不能用知识分数代替。skill 的适用范围、四维评分及失败分析继续遵循[数据处理接口](skill-growth.md#数据处理接口与评分范围)，完全不接执行、审批、自动重试或路由。

## 路线 A 的收尾顺序

1. 收尾模型读取项目整体架构与需求、模块架构与需求、精确方案包及测试证据；形成对不同实现的评分、验收判断依据、整理建议和入库提案。
2. 整理或去耦改变包内容时形成新版本，按受影响验收项重新核验，再准备固定的包摘要和证据。模型可以提出不采用某方案并保留其资料的建议；留存与主库采用分别记录，见[并行分支与方案包](parallel-branches.md)。
3. 人类确认绑定精确项目/模块范围、包 revision 与 digest、项目基线、需求及验收版本、测试证据和审阅依据。待确认提案不能当作批准；人类拒绝或要求补证据时不执行入库。
4. 模型或编排层执行这次确认覆盖的并入动作。并入开始前，包字节或影响决策的依据变化须提交新提案、重新验收和人审；非决定性备注变化不扩大批准范围。执行已经开始后的撤销及未知效果沿用已有生命周期纪律，不能通过改写旧确认或重放未知写入解决。
5. 入库是否完成以持久回执及实际目标效果判定，模型“已完成”说明不能替代已应用事实。SCM 目标需遵循[外部效果映射](scm-effect-mapping.md)，存储收敛要求见[双层存储](dual-layer-storage.md)。

上述顺序是待实现要求，不能按当前命令名推断为可调用的新流程。失败、未采用及尚待确认的过程记录也有留存价值，不能伪造成验收通过或批准。
