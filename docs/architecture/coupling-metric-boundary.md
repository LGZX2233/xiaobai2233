# 耦合度量与架构审阅边界

文档版本：1.1.0；更新日期：2026-10-12（Asia/Shanghai）。源码依据：`16410c9fbf4a8507445b4603e371e701614e4499`。归属 [K-EXECUTION](../modules/nodes/execution.md) 与 [K-QUERIES](../modules/nodes/queries.md)，对应 [REQ-BOUNDARY-10](../requirements/2026-10-12-kernel-boundaries.md)。状态为设计说明及静态核对，未实现任何度量投影、未行为验证，`release_approved=false` 不变。

## 需求与责任

用户要求收尾模型“处理模块杂乱和保持低耦合高聚合”。本文沿用“度量进内核，裁决进模型”的分工：内核数据处理提供有版本、有依据的读数；模型结合项目及模块架构、需求和实际代码提出整理建议。这里的模型裁决指技术判断与建议，最终入库授权遵循已选[路线 A](model-review-identity.md)，由人类确认。

“高聚合”需要可检查的项目定义；模块内部职责集中、共同满足同一组需求是候选解释。依赖数低不能单独证明模块职责合理，拆分出更多模块也不自动代表架构改善。

## 度量候选与可复现要求

| 指标 | 候选来源 | 能说明什么及其限制 |
| --- | --- | --- |
| 出度/入度 | `docs/modules/registry.json` 的 `depends_on` | 声明依赖数与被依赖数；不保证文档声明等于运行依赖 |
| 依赖方向 | `depends_on` 与明确的架构分层 | 是否违反项目定义的层级规则；导航父子关系不能直接当作技术分层 |
| 强弱关系计数 | `depends_on`、`related_to` 分别统计 | 展示依赖及关联分布；关联比值不是质量分 |
| 代码级导入耦合 | 固定源码版本的 import 图 | 更接近实际代码依赖；动态调用及外部系统仍可能缺失 |
| 模块职责与需求分布 | 项目/模块需求映射、公开接口和验收项 | 可辅助检查职责集中；统计本身不代替模型解释职责是否合理 |

当前 registry 是文档索引，不是运行 Store 的 revision；分析时需固定其实际文件版本或字节摘要。源码指标需固定源码 revision，未提交改动需另存准确输入，不能仅写基准 HEAD。未来业务记录指标按明确项目、Store 和 `as_of` 读取。

同一输入范围、内容和度量规则版本应产生相同读数，缺失来源需报告 gaps。与[消费者一致性](consumer-consistency.md)一样，digest 不能替代可读取的材料。不同来源水位或缺口的结果不能直接当作同一帧比较。

## 模型审阅与人工确认

收尾模型读取度量、固定方案包、架构及需求版本，说明哪些模块职责分散、依赖不合理、建议如何整理，以及对验收范围的影响。模型意见是留存的意见事实，不能把其中的判断写成客观验证已通过。

整理改变实现时先产生新包，再执行受影响的测试与验收；评分和耦合读数须引用新版本。最终人工确认绑定该包及其依据，流程由[模型收尾身份](model-review-identity.md)统一定义。单一分数、低依赖数或“已去耦”文字不能代替验收及人工许可。

| 事项 | 责任 | 对入库的作用 |
| --- | --- | --- |
| 计算并记录度量 | 内核数据处理或受版本控制的采集器 | 提供可检查依据，缺口保持可见 |
| 定义度量规则 | 度量实现者维护规则版本 | 保证读数含义和可复现性，未经验证不能宣称质量保证 |
| 判断是否杂乱、提出解耦方式 | 收尾模型 | 提出技术建议与理由 |
| 在授权范围内整理模块 | 执行模型或收尾编排 | 产生新实现与新证据，不自授审批 |
| 确认具体包是否入主库 | 人类 | 采用路线 A 的最终许可，结合[收敛要求](dual-layer-storage.md) |

## 候选方案、取舍与影响

首版可以只读取文档声明依赖，成本低且易固定输入，但覆盖范围有限；引入代码图及需求关联后更接近实际架构，需额外采集、版本关联和缺口表达。两种方案都需要模型解释指标，不能把指标权重写成未经论证的自动裁决。

候选实现是 `QueryService` 的只读度量视图，例如尚未存在的 `coupling_report`，或带来源清单的独立数据处理报告。只读计算不推进业务状态；如需持久审阅依据，另行设计报告记录和精确引用。此处未选定新命令、schema 或权重。

skill 的四维评分与失败分析是另一数据处理接口，遵循[适用范围](skill-growth.md#数据处理接口与评分范围)，完全不接执行。方案评分、架构度量和 skill 评价不能互相替代，也不能自动调用审批、执行或重试。
