# 项目记录与交接

本公开接入版整理自 kernel-maintain-records 2.5.0。

1. 从工作所属模块的记录或明确指派的待办开始。复用同版本已核对的事实。
2. 在依赖它的工作开始前，保存新需求、授权、实质决定、阻塞错误及影响未知的操作。区分用户原话与分析，注明版本、范围、验收和未决项。
3. 在自然检查点合并日常记录。标记尚未同步的视图，并以原操作回执核对未知结果。
4. 普通任务可按简短目标自主计划，无须另填表单。收尾时先找受影响模块的权威现状原文，再据实际结果改写结论、证据和待验边界，最后从原入口读回并交接。受权限或冲突阻塞时记录原因、证据与接手方，标记 `pending_sync`。当前由执行模型按规范办理，宿主自动回写仍待验证。
5. 在当前权限与可信作用域内操作。将人审决定和样本关联到原版本。在交接中列出实际运行的检查与尚待核验的范围。
